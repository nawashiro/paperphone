# Design

## 骨子

主画面`application_view.py`と各選択モジュールの既存構成を維持し、**規格の追加は最小の差分**で行う。 一部の要件は Adw.Dialog（libadwaita 1.5〜）由来の浮き板に頼るため、兼用の閉じ手段は`Adw.Dialog`の動作に実装寄りに検証した上で決める。

## 対話の閉じ手段（#10）

- 現状: `_dialog()`（`application_view.py:349`）は`Adw.Dialog`を`set_child`だけで提示する。a11y上は`sheet.close`があるが、画面には閉じボタンが現れない。Escapeでは閉じる（2026-11-10にVMで確認）。
- 方策: 対話内の末尾（または上部）に「閉じる」ボタンを一律に置き、`dialog.close()`を呼ぶ。libadwaitaが閉じボタンを自動で出す版では二重にならないよう、実装は**ボタンが対話の唯一の可視閉じ手段になる**形にして、挙動を テストで確認する。

## 一覧の収容（#15）

現在のソース一覧は`Gtk.ListBox`をそのまま対話に入れており、件数が増えると対話自体が伸びる。対話の中身に`Gtk.ScrolledWindow`（最大高さを`set_size_request(-1, N)`で規定）を挟み、Refresh・Cancelはスクロール外の固定行に残す。連絡先一覧（#8）も同じ構成にし、対話自体の高さはウィンドウ内に収める。

## 危険操作の分離（#16）

設定は`Save settings`直下に`Delete stored map data`（`application_view.py:209-210`）。**削除を「危険な操作」という独立セクション**（見出し＋違うスタイルのボタン）へ移し、'+ Save' と隣れ合わせない。スタイルはヘッダと類似しない赤系など汎用の区別ではなく、見出しのセクション分離＋距離で判別させる。

## 見出しと操作の区別（#7）

- 現状: `_section()`の見出し（グレー帯・中央寄せ）と、`Gtk.Stack`のタブ／ボタンが同じ慣行に載る（Today/Upcoming等）。STYLESはGTK4の標準CSSに山上せる。
- 方策: 見出しは小さめのラベル（ヘッダのサブタイトル相当・左寄せ）にし、操作要素は標準のボタン/タブの外観に戻す。新たなカスタムCSSは使わない。**#9の「左揃えに統一」は見送り**（利用者の2026-11-10判断）— 見出しの配置変更はしない。

## 連絡先（#8）と写真プレビュー（#6）

- 連絡先は`contact_selection.py`（主画面上の一覧）。現状は固定高の白枠が上の2件しか見えない（ issueのスクショ）。`Gtk.ScrolledWindow`の高さを伸ばし、一覧下の操作は固定。7件の選択上限（既定仕様）は維持。
- 写真プレビューは`booklet_asset_view.py:78-81`の`Gtk.Image`。`set_pixel_size()`をではなく、`set_size_request`で高さを確保して`set_expand`で埋める。「写真が消える」ことなく、枠は該当面の複製領域に相当する大きさ（既存の`MAP_REGION`等に合わせて調整、MUSTは最終実測で確認）。

## 地名検索のフォーカス（#18）

`place_selection.py`の`_set_busy(True)`が検索中に全エントリを`set_sensitive(False)`にし、GTKがインセンティブでフォーカスを剥がすため。方策：

- 検索処理（debounce後の検索・結果待ち）ではentryの**無効化をしない**。索引の生成／読込（`load_extract`一道）のみ、従来どおり入力禁止にする。
- 無効化以外の進行可視化（既存の`status`・`progress`）は維持。
- テストは`tests/test_place_selection.py`に「検索中にentryがsensitiveであり、フォーカスを失わない（focus-in後に検索→busy→sensitiveであること）」を追加。

## 起動時の自動再取得（#13）

- 現状: 起動時に`list_sources()`（列挙）まで。設定永続化に選択情報はすでに保存されている。再取得は「Refresh selected sources」押下のときだけ。
- 方策: 起動後、列挙完了 → 保存済み選択がある場合に`refresh_sources()`を一度だけ呼ぶ（手動操作の代わり）。失敗は既存の状態語経由で表示、**追加の自動再試行はしない**。テストは**モックによる試験**（EDSが起動しているかは実機確認）＋パーミッション拒否などの既存経路をモック試験（`tests/test_eds_refresh.py`など）＋自動試験で確認。VMではD-Busが足りないので手動実装上の確認とGUI確認は実機待ち。
