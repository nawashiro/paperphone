# Proposal

## Why

tangledのopen issueのうち、対話・一覧まわりの操作性扱い8件（#6, #7, #8, #10, #13, #15, #16, #18）が、扱いません。共通の原因は、主画面の要素をモーダルの浮き板とタブで組む今の実装が、閉じ手段・視覚の区別・収容サイズ・処理中の入力継続まで規格として定めていないことにありますわ。verify結果:

- **#10**: Sources/設定の浮き板に閉じボタンがなく、Escapeの非表示操作でのみ閉じる（2026-11-10にVM再現済み。a11y上は`sheet.close`があるが可視の痕跡は出ていない）
- **#7**: セクション見出し（グレーの帯・中央寄せ）とタブ／ボタンが同じスタリング（同一屏で観測、「Today/Upcoming/No due date」列）
- **#15**: ソース一覧のリストは最大高さもスクロールも無く、数が多いと溢れ出す
- **#16**: 設定で「Save settings」と「Delete stored map data」が隣り合う同じ形のボタン（スクショ観測済み）
- **#8**: 連絡先はページ内の固定小領域にスクロール式で、見える量が2件程度
- **#6**: 写真を選んでもプレビューが数px級の灰色小片（issue #6のスクショで確認）
- **#18**: 地名検索で3〜5文字タイプするたび`_set_busy`が検索栏を`set_sensitive(False)`にし、GTKがフォーカスを奪って入力が続かない（`place_selection.py`の`_set_busy`/検索経路で特定）
- **#13**: 起動時のソース列挙と選択設定の永続化は実装済みだが、前回選択済みソースの**再取得**は「Refresh」を押す必要がある

## What's Changed

- 浮き板（Adw.Dialog由来の対話）に**見える閉じる手段**を置く。Escapeでの閉じは保持する
- ソース一覧に最大高さとスクロールを設け、下段の操作（Refresh・Cancel）は常に到達可能のまま
- 設定対話で**危険な操作（保存データの削除）を区別した別のセクション**へ分ける
- セクション見出しと操作要素（タブ・チェック・ボタン）をスタイルで区別する
- 連絡先選択に、一覧の高さとスクロール（またはページ送り）を設け、選択対象を確認できる大きさにする
- 写真プレビューを選択領域の高さに収まる大きさに引き上げる
- 地名検索中に検索栏のフォークスと入力を失わせない（索引読込中のみ無効化し、検索経路では無効化に替わらない）
- 起動時に、保存済み選択を含むソースの**再取得を一度**実行する。失敗時は手動Refreshを残す

対象外：**#9（中央揃え／左揃えの混在）は利用者の2026-11-10の判断で見送り**（中央寄せの見出しはGNOMEの慣例にも一致する）。#1〜#4・#11〜#14・#17 は他のchangeまたは既存対応。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `desktop-application`：対話の閉じ手段、見出しと操作の区別、リストの収容、危険操作の分離、連絡先と写真の選択操作性、検索中の入力継続、起動時の自動再取得を規格に追加する。
