# Spec Delta

## Purpose

このcapabilityは、PCで外出前の冊子を準備できるGNOME向けアプリの画面構成・対話・設定を扱う。本deltaは、対話まわりの取り扱い品質を規格に加える。既存の「部分的な取得失敗」（ソース列挙の自動化・状態語の短表示）、「設定の保存」（選択の永続化）と併用する。

## ADDED Requirements

### Requirement: 対話の見える閉じる手段

主画面から開いた対話（取得元の一覧、設定、その他の浮き板）は、可視の閉じる操作を提供しなければならない（MUST）。キーボードで閉じる経路（Escape等）も維持しなければならない（SHALL）。閉じる操作のために主画面の他の操作を先に実行させてはならない（MUST NOT）。

#### Scenario: マウスだけで対話を閉じる

- **WHEN** 利用者が取得元の対話を開く
- **THEN** 対話の中に閉じるボタンがあり、押すと対話が閉じる

#### Scenario: キーボードで対話を閉じる

- **WHEN** Escapeキーを押す
- **THEN** 対話が閉じ、入力フォーカスが主画面に戻る

### Requirement: 一覧の収容

取得元の一覧など、件数が可変のリストは最大の高さを持ち、超過はスクロールで閲覧できなければならない（SHALL）。リストの下段にある操作（再取得・中止など）は、リストの長さに依らず常に到達可能でなければならない（MUST）。

#### Scenario: ソースが多いとき

- **WHEN** ソースが画面に並ばない数だけある
- **THEN** 一覧は設定した高さ内でスクロールでき、操作ボタンは元の位置で押せる

### Requirement: 危険な操作の分離

保存データの削除のような破壊的な操作は、保存系の操作（設定の保存・画面を閉じるなど）と区別した領域にあり、誤って押す配置にはならない（MUST NOT）。区別はラベルの文言だけに依存しない（SHALL）。

#### Scenario: 設定で削除と保存が隣れ合わない

- **WHEN** 設定対話を開く
- **THEN** 「地図データを削除」は保存操作から分離した領域にあり、視覚上も区別される

### Requirement: 見出しと操作要素の区別

セクション見出しと、押せる要素（タブ・チェック・ボタン）は、スタイルで区別されなければならない（SHALL）。押せる要素が見出しと同一の慣行で描かれてはならない（MUST NOT）。

#### Scenario: タブ列を見る

- **WHEN** Tasks領域の「Today / Upcoming / No due date」を見る
- **THEN** これらが押せることと、直上の「Tasks」見出しの区別が視覚で分かる

### Requirement: 連絡先の一覧選択

連絡先の選択領域は、選択対象を確認できる大きさを持ち、一覧の閲覧に独立したスクロールまたはページ送りを提供しなければならない（SHALL）。見える件数が既定の選択上限（7件）より少ないままでは選べないようにしてはならない（MUST NOT）。

#### Scenario: 連絡先を一覧から選ぶ

- **WHEN** 端末に複数の連絡先がある
- **THEN** 一覧の大部分が表示され、スクロールで残りに届き、選択操作はサイズ不足で失敗しない

### Requirement: 写真プレビューの視認性

ローカルの写真を選択したとき、プレビューは選択領域に見える大きさで表示しなければならない（SHALL）。数十px以下の破片のような表示は許容しない（MUST NOT）。プレビューの配置は冊子の該当面（左上の複製領域）に一致しなくてよい（SHALL）。

#### Scenario: 写真を選ぶ

- **WHEN** ローカルの写真を選択する
- **THEN** 選択領域の高さに合わせたプレビューが表示される

### Requirement: 地名検索中の入力継続

出発地・目的地の検索は、検索・読込処理の進行中も検索欄のフォーカスと入力を失わせてはならない（MUST）。派生データの初期読込など終了が待てる段階まで、検索欄を無効化してはならない（MUST NOT）。処理の進行は進捗表示と状態文言で示す（SHALL）。

#### Scenario: 連続で地名を打つ

- **WHEN** 出発地の検索栏へ文字を入力して検索が走る
- **THEN** 検索の間もフォーカスは栏に残り、引き続き入力・訂正ができる

### Requirement: 前回取得設定の自動反映

起動時に、前回の実行で選択・保存された内容確認用ソースの再取得を一度だけ自動で行わなければならない（MUST）。この自動取得の途中でも、利用者は中止を押せなければならない（SHALL）。自動取得が失敗した後の追加の自動再試行は行わない（MUST NOT）。手動の再取得は常に使える（SHALL）。

#### Scenario: 前回選択のまま起動する

- **WHEN** アプリを起動する
- **THEN** 保存済み選択のソース列挙と、選択済みソースの再取得が一度だけ行われ、各行に短い結果状態が表示される

#### Scenario: 自動取得を停める

- **WHEN** 自動取得の実行中に中止を押す
- **THEN** 実行が止まり、以後は手動の再取得でのみ更新される
