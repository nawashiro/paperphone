# Spec Delta

## MODIFIED Requirements

### Requirement: 場所検索はローカルで完結する
アプリは取得済みの都道府県OSM抽出から一度だけ生成した派生データ（ローカル索引）で出発地と目的地を検索しなければならない（SHALL）。派生データが利用可能であれば、検索は実行時にPBF/XMLを走査または展開せず、入力と同時に候補を返さなければならない（SHALL）。検索中に外部の位置情報サービス・Web APIを呼び出してはならない（MUST NOT）。検索は利用者の入力と同時に候補を出し、検索・取り消しのための専用ボタンを置いてはならない（MUST NOT）。候補と選択結果の表示は人間可読な名称だけにし、種別名・座標・内部IDや現在地の機械向けラベルを載せない。内部データには引き続き種別と座標を持つ。

#### Scenario: 入力と並行した候補
- **WHEN** 利用者が検索窓に文字を入れる
- **THEN** 選択ボタンを押さずに、派生データ由来の候補が名称だけの状態で並び、選択できる

#### Scenario: 曖昧な名前で探す
- **WHEN** 部分一致や異なる表記（漢字・かな・英語名など）で入力する
- **THEN** 名称だけの候補一覧が提示され、利用者は名称から応じた地点を選択できる

#### Scenario: 検索結果がない
- **WHEN** 派生データに一致する地点がない
- **THEN** 結果なしを短く示し、架空の地点を出さず、他の機能の利用は妨げない

#### Scenario: 現在地を出発地にする
- **WHEN** 位置情報が許可され、現在地が抽出範囲内にある
- **THEN** 現在地を既定の出発地候補として選択できる

#### Scenario: 派生データの生成中
- **WHEN** 抽出は保存済みだが派生データの生成が完了していない
- **THEN** 進捗を示して検索を待たせ、生成完了後に通常の検索に戻る

### Requirement: 徒歩経路の取得
アプリは抽出入手時に一度だけ生成した派生データ内の歩行者グラフを使い、出発地と目的地の間の徒歩経路を取得し、経路・距離・目安時間を紙面モデルへ提供しなければならない（SHALL）。経路の要求は出発地・目的地の周辺範囲を派生データへ照会して組み立てなければならない（SHALL）。同じ抽出版での経路要求ごとにPBF/XMLを全文走査してはならない（MUST NOT）。派生データにはOSM由来の名称・座標・歩行対象の経路情報だけを入れ、検索語・選択履歴・利用者識別情報を書き出してはならない（MUST NOT）。実在しない経路を推測して描いてはならない（MUST NOT）。

#### Scenario: 徒歩経路が存在しない
- **WHEN** グラフ上に到達可能な経路が返らない
- **THEN** 経路なしと表示し、地図機能を除いて出力を続けられる

#### Scenario: 抽出範囲外の地点
- **WHEN** 出発地または目的地が都道府県抽出の範囲外にある
- **THEN** 実現できない理由を明示し、架空の経路を描かない

#### Scenario: 通信なしで経路を得る
- **WHEN** 取得済みのOSMデータと派生データが存在する
- **THEN** ネットワーク接続なしで検索・経路・地図描画を完了できる

#### Scenario: 目的地を替えた要求
- **WHEN** 同じ抽出版に対して目的地を替えた経路を連続で要求する
- **THEN** 派生データの範囲照会で応答し、要求のたびのPBF/XML全文走査をしない

## ADDED Requirements

### Requirement: 派生データの生成と保持
アプリは都道府県抽出の保存・更新の直後に、その抽出版に対応する地名索引と歩行者グラフを含む派生データを一度だけ生成しなければならない（SHALL）。派生データの生成中は進捗を表示し、取り消せても取り消し後に索引やグラフの一部分だけを使ってはならない（MUST NOT）。派生データの先頭は抽出版に紐付き、版が変わった時だけ再生成しなければならない（MUST）。派生データの削除は抽出データの削除に含めなければならない（SHALL）。生成に失敗した場合はその理由を短く示し、地図機能を除いた冊子作成を継続できなければならない（SHALL）。

#### Scenario: 取得直後の生成
- **WHEN** 新しい抽出版が保存される
- **THEN** 派生データの生成が始まり、進捗が表示され、完了後に検索・経路が派生データを利用する

#### Scenario: 版が替わった時の再構築
- **WHEN** 利用者が抽出を更新して版が変わる
- **THEN** 旧版の派生データは廃棄され、新版に対応する派生データが再び一度だけ生成される

#### Scenario: 削除に含める
- **WHEN** 利用者が設定から地図データの削除を選ぶ
- **THEN** 抽出ファイルとともに派生データも削除される

#### Scenario: 生成の失敗
- **WHEN** 派生データの生成がエラーで終わる
- **THEN** その理由が短く示され、地図ページを除いた冊子の作成は続けられる
