# 印刷地図派生データ第2版の実測検証（タスク4.1）

## 条件

- 抽出: movisdaの愛媛県（JP-38）実PBF、`JP-38-latest.osm.pbf`、30,396,428バイト、sha256 `da4dec9e6965a95fb2a0b1125199fad9cd1f3a82230837db79e214ace23e24cb`（2026-11-10取得）。
- 前後を同じPBF・同じ手順に通して比較する。前=第1版（コミット `cca0a32`時点、way単位・簡素化なし・ラベル重要度なし）、後=第2版（`e842336`以降、way連鎖統合・簡素化・ラベル重要度）。
- 計測環境: `python:3.11-slim`コンテナ（PyPI版osmium・shapely・pycairo・PyPI要件）。絶対値を場当たりで比較しないため、同一コンテナで両版を連続実行。
- 計測スクリプト: `build/measure/measure_run.py`（sqliteのBLOBを各版の`_unpack_paths`で展開し点数を数える）。

## 実測（愛媛県・第1版 → 第2版）

| 指標 | 第1版 | 第2版 | 変化 |
|---|---|---|---|
| 派生SQLiteサイズ | 487,034,880 B | 471,814,144 B | −3.1% |
| 生成時間 | 181.3秒 | 192.9秒 | +6.4% |
| 格納道路（way/連鎖）数 | 154,553 | 108,025 | −30.1% |
| 格納道路の格納点数 | 1,985,391 | 1,471,777 | −25.9% |
| 格納面（ポリゴン）数 | 323,092 | 323,092 | − |
| 格納面の格納点数 | 2,727,932 | 2,553,906 | −6.4% |
| ラベル数 | 22,790 | 22,790 | − |
| 徒歩グラフ（geo_nodes / ped_way_nodes） | 4,790,613 / 1,924,873 | 同左 | − |

## 読み

- 道路はway連鎖統合でレコードと格納点が2割以上減る。みかけ上のSQLサイズ削減は緩やか（−3.1%）で、実体は「1レコードが1本の見た目の通り」への変質にあり、印刷時の経路点の取捨と描画の整理の減人力に効く。
- 簡素化で面（水辺・区画面など）の点も6%強削る。ラベル数は印刷前段の省略条件が変わらない限り同数。
- 生成は第2版が+c.12秒（+6.4%）。簡素化・統合は構築時の一度だけ実施という設計に沿うコストで、実行時照会側に影響しない。
- 愛媛県で接し上記を記録した。東京のような大規模県では比率はほぼ同型とみてよい（統合率は路網密度で変わる）。
