# Design

## Context

`application_view.py` はStack＋StackSidebarで9〜10ページを構成する: Settings / Sources / Contacts / Calendar / Tasks / Weather / Walking map / Photos / Paper apps / PDF。ヘッダーバーにSettingsボタンがあり、起動時の初期ページは "sources"（ソース管理）である。起動直後にソース管理が目に入る構成で、冊子を作る目的は奥にある。

既存の選択ビュー（連絡先・TODO・天気・徒歩地図・紙アプリ・写真）は独立したウィジェットとして implementaion 済みで、`ApplicationView` の注入可能なfactory構成（`contact_selection` 等を差し替えられる）は画面の再配線を簡単にする。設定の保存・復元、部分的な取得失敗の表示、キーボード操作はすでに spec の要件があり、再実装の対象ではない。

## Goals / Non-Goals

**Goals:**
- 主画面を 内容選択 → プレビュー → 出力 の単一フローに再構成する。起動時の初期表示は内容選択。
- ソース一覧・設定・言語はヘッダーバー起点のダイアログへ移す。既存の状態表示・設定保存の振る舞いはダイアログ内で維持する。
- 各選択ビューの再利用。ロジックの書き替えはしない（UIの改良）。

**Non-Goals:**
- 視覚的な新設やアイコン・アニメの追加、ダークテーマ対応詳細（既存の明暗追従はそのまま）、ライト・キーボード操作の再定義。`lighten-osm-pipeline`（地図関連の速度は既に派生データが負担する）。

## Decisions

**構造: Stackサブビューの削除＋主画面ウィジェットの組み立て**
既存の9ページを「カテゴリセクション（折りたたみ可能）＋出力パネル」の主画面1つに置き換える。GTKの `Gtk.Revealer`・`Adw.PreferencesGroup` のような標準部品で折りたたみを表現し、独自のウィジェット階層を増やさない。連絡先・予定・TODOの別々はセクション内の見出しで維持する。

**ボタン起点の二次画面: ダイアログに統一**
設定・ソース・出力履歴は `Adw.PreferencesDialog`／`Adw.Dialog` で表現する。Stackページとして持つのを廃止し、主画面の選択状態への影響を消す。

**出力パネルの統合**
PDF保存・印刷・生成進捗は既存の `output` ビューの内容を主画面の終端パネルに置き、現在個別ページ（"pdf"）として置く形をやめる。部分的な取得失敗の表示・生成中断も同じパネルに載せる。

**起動時の初期表示**
`sources` を指す現在の実装から「内容選択」へ変える。起動時のソース列挙は裏で自動に行う（現行の「起動時の自動列挙」要件は維持）。

**UI文字の整理**
文言 divergence（パネル由来の英語String、日本語と英語の対）は `i18n.py` と文言一覧に整合させる。名画面の統合で文言の重複・複製を減らす。

## Risks / Trade-offs

- [キーボード操作とアクセシビリティが再確認必要] → セクションの折りたたみとダイアログないしパネルの下半分に焦点が移る。既存のラベル・関係ラベルを再利用し、キーボード操作の確認結果を記録する。
- [セクション多重化での行列アコーディオンの目変] → fold/unfold 症状の最小化。折りたたみ状態は設定ファイルに保存しない（起動時はすべて初期状態）。
- [既存の挙動と不和になる部分の肩代わり] → 連絡先・TODO・予定の「別々のページ」要件をセクション内の区別に読み替える（specに明記済み）。

## Migration Plan

一度に主画面を置き換える。旧9ページ構成の下回りは、Stack削除とともに破壊的に除去する。既存の設定ファイルの読み書き構造は変えず、選択状態の保存のみを維持する（折りたたみ状態は保存しない）。

## Open Questions

- 視覚の詳細（フォント、余白、セクションのアイコン）は実装時にGNOME HIG基準で決める。設計の判断に影響しない。
