# Spec Delta

## MODIFIED Requirements

### Requirement: GNOMEに適した操作
アプリはGNOMEネイティブの画面、ヘッダーバー、設定、ファイル選択、保存と印刷の操作を提供し、キーボード操作とアクセシブルなラベルに対応しなければならない（SHALL）。英語と日本語の表示を提供しなければならない（SHALL）。アプリの主画面は「冊子に載せる内容を選ぶ」画面でなければならず（SHALL）、起動時に内容選択から表示しなければならない（MUST）。ソース一覧・設定・言語などの二次操作はヘッダーバーと専用のダイアログから辿らせ、主画面の選択と出力の流れから独立させなければならない（MUST）。出力（PDF保存・印刷）は主画面の終端から直接開けなければならない（SHALL）。折り畳み配置のプレビューは主画面から直接開けるようにしなければならない（SHALL）。

#### Scenario: キーボードで冊子を準備する
- **WHEN** 利用者がキーボードで機能を選択してプレビューを開く
- **THEN** フォーカス位置と各操作の名前が分かり、マウスなしで内容選択から出力までの主要操作を完了できる

#### Scenario: 日本語環境で起動する
- **WHEN** 日本語ロケールで起動する
- **THEN** UIと標準ダイアログが日本語で表示され、英語環境でも同等の機能を利用できる

#### Scenario: 起動直後の主画面
- **WHEN** アプリを起動する
- **THEN** 内容選択画面が表示され、ソース管理や設定のページが前に出ない

#### Scenario: 設定とソースへの到達
- **WHEN** 利用者がヘッダーバーの設定ボタンを押す
- **THEN** 設定やソース一覧が専用のダイアログで開き、閉じると主画面の選択状態が保たれる

#### Scenario: 主画面から出力する
- **WHEN** 利用者が主画面で内容を選び終える
- **THEN** PDF保存・印刷の操作を主画面の流れの中で開き、生成の進捗と失敗が同じ流れで見える

#### Scenario: プレビューの確認
- **WHEN** 利用者が主画面でプレビューを開く
- **THEN** 折り畳み配置を確認でき、選択を変えて再確認できる

### Requirement: 連絡先と予定とタスクの分離
連絡先・予定・TODOは主画面の選択セクションの中でも区別して扱わなければならない（SHALL）。連絡先のセクションに予定やタスクを混在させない。選択セクションは見出しで種別をまとめ、各行に種別名を繰り返し付けてはならない（MUST NOT）。

#### Scenario: 選択画面での区別
- **WHEN** 利用者が主画面で連絡先を選ぶ
- **THEN** 連絡先のセクションだけが開き、予定やTODOの行が混ざらず、見出しで種別がまとめられる

## ADDED Requirements

### Requirement: 画面構成の単一フロー
アプリの主画面は内容選択・プレビュー・出力の順に進む単一の流れでなければならず（SHALL）、流れの外に視覚的な分類ページを置いてはならない（MUST NOT）。カテゴリ（予定・TODO・連絡先・天気・徒歩地図・メモ・写真・紙アプリ）ごとの選択セクションを主画面内に収め、セクションの開閉は利用者が行えなければならない（SHALL）。セクションの選択状態と出力の生成状況は主画面から確認できなければならない（SHALL）。

#### Scenario: 主画面の流れ
- **WHEN** 利用者が主画面を操作する
- **THEN** 内容選択からプレビュー・出力までは同じ画面の流れで進み、機能ごとの個別ページを横断しない

#### Scenario: セクションの開閉
- **WHEN** 利用者が不要なカテゴリのセクションを閉じる
- **THEN** そのセクションは折りたたまれ、選択中の内容と出力ボタンは画面上に残る

#### Scenario: 分類ページの不在
- **WHEN** アプリの画面を確認する
- **THEN** ソース一覧・設定・カテゴリ配下を主画面と同列のページとして置いてはいない
