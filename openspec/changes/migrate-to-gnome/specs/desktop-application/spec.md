# Spec Delta

## Purpose

PCで外出前の冊子を準備できるGNOME向けアプリとして、標準的な操作、システム設定との整合、安全な外部サービス利用を提供する。個別のデータソースが利用できない場合でも、利用可能な内容による冊子作成を継続できるようにする。

## ADDED Requirements

### Requirement: GNOMEに適した操作
アプリはGNOMEネイティブの画面、ヘッダーバー、設定、ファイル選択、保存と印刷の操作を提供し、キーボード操作とアクセシブルなラベルに対応しなければならない（SHALL）。英語と日本語の表示を提供しなければならない（SHALL）。

#### Scenario: キーボードで冊子を準備する
- **WHEN** 利用者がキーボードで機能を選択してプレビューを開く
- **THEN** フォーカス位置と各操作の名前が分かり、マウスなしで主要操作を完了できる

#### Scenario: 日本語環境で起動する
- **WHEN** 日本語ロケールで起動する
- **THEN** UIと標準ダイアログが日本語で表示され、英語環境でも同等の機能を利用できる

### Requirement: システムに従う日時
アプリは日付判定・日時表示・印刷にシステムのタイムゾーンを使用し、対象日時の夏時間を反映しなければならない（SHALL）。日本時間や現在の固定UTCオフセットによる補正を行ってはならない（MUST NOT）。

#### Scenario: 夏時間をまたぐ予定
- **WHEN** 現在と異なるUTCオフセットが適用される日時の予定を表示する
- **THEN** 対象日時に適用されるシステムタイムゾーンの時刻を表示・印刷する

#### Scenario: システムタイムゾーンが変わる
- **WHEN** システムのタイムゾーンを変更して画面を再表示または冊子を再生成する
- **THEN** 新しい設定に基づいて対象日、時刻とTODO分類を再計算する

### Requirement: 許可された現在地取得
アプリはPCの位置情報を許可に基づいて取得し、天気の取得先へ座標を送信することを説明しなければならない（SHALL）。位置情報が拒否・利用不能の場合は理由を表示し、位置情報を必要としない機能を継続可能にしなければならない（SHALL）。

#### Scenario: 位置情報の拒否
- **WHEN** 利用者が位置情報へのアクセスを拒否する
- **THEN** 天気を取得できない理由を表示し、位置情報要求を繰り返さず、メモや写真などの冊子作成を継続できる

### Requirement: 部分的な取得失敗
アプリはデータソースごとの取得状況と失敗理由を表示し、失敗した内容を除いた出力を利用者が確認して継続できるようにしなければならない（SHALL）。空データと取得失敗を区別しなければならない（SHALL）。

#### Scenario: カレンダーだけが取得できない
- **WHEN** 予定の読取が失敗し、他の内容は利用できる
- **THEN** 予定の失敗理由と除外を表示し、利用者の確認後に他の内容でPDFを生成できる

### Requirement: 配布環境でのデスクトップ連携
配布されたGNOMEアプリはホストの予定・タスクリスト・アドレス帳、位置情報、ファイル保存と印刷に必要最小限の権限で接続し、未設定の場合は設定案内を提供しなければならない（SHALL）。

#### Scenario: タスクリストが未登録
- **WHEN** デスクトップ側に利用可能なタスクリストが登録されていない
- **THEN** 「未完了タスクがない」状態と区別し、CalDAVタスクリストを登録するための案内を表示する
