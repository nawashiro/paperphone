# Spec Delta

## Purpose

PCで外出前の冊子を準備できるGNOME向けアプリとして、標準的な操作、システム設定との整合、安全な外部サービス利用を提供する。個別のデータソースが利用できない場合でも、利用可能な内容による冊子作成を継続できるようにする。

## ADDED Requirements

### Requirement: GNOMEに適した操作
アプリはGNOMEネイティブの画面、ヘッダーバー、設定、ファイル選択、保存と印刷の操作を提供し、キーボード操作とアクセシブルなラベルに対応しなければならない（SHALL）。英語と日本語の表示を提供しなければならない（SHALL）。

#### Scenario: キーボードで冊子を準備する
- **WHEN** 利用者がキーボードで機能を選択してプレビューを開く
- **THEN** フォーカス位置と各操作の名前が分かり、マウスなしで主要操作を完了できる

#### Scenario: 日本語環境で起動する
- **WHEN** 日本語ロケールで起動する
- **THEN** UIと標準ダイアログが日本語で表示され、英語環境でも同等の機能を利用できる

### Requirement: システムに従う日時
アプリは日付判定・日時表示・印刷にシステムのタイムゾーンを使用し、対象日時の夏時間を反映しなければならない（SHALL）。日本時間や現在の固定UTCオフセットによる補正を行ってはならない（MUST NOT）。

#### Scenario: 夏時間をまたぐ予定
- **WHEN** 現在と異なるUTCオフセットが適用される日時の予定を表示する
- **THEN** 対象日時に適用されるシステムタイムゾーンの時刻を表示・印刷する

#### Scenario: システムタイムゾーンが変わる
- **WHEN** システムのタイムゾーンを変更して画面を再表示または冊子を再生成する
- **THEN** 新しい設定に基づいて対象日、時刻とTODO分類を再計算する

### Requirement: 許可された現在地取得
アプリはPCの位置情報を許可に基づいて取得し、天気の取得先へ座標を送信することを説明しなければならない（SHALL）。位置情報が拒否・利用不能の場合は理由を表示し、位置情報を必要としない機能を継続可能にしなければならない（SHALL）。

#### Scenario: 位置情報の拒否
- **WHEN** 利用者が位置情報へのアクセスを拒否する
- **THEN** 天気を取得できない理由を表示し、位置情報要求を繰り返さず、メモや写真などの冊子作成を継続できる

### Requirement: 部分的な取得失敗
アプリはデータソースごとの取得状況と失敗理由を示し、失敗した内容を除外して残りの内容だけを出力しなければならない（SHALL）。空データと取得失敗を区別しなければならない（SHALL）。失敗した内容や利用不可能な付加機能の除外を利用者に再確認させてはならず（MUST NOT）、生成は他の内容だけですぐに続行できなければならない（SHALL）。ソース一覧は起動時に自動で取得しなければならず（SHALL）、利用者に毎回の手動列挙を求めてはならない（MUST NOT）。読取状態は同じ行の右端に短く表示しなければならない（SHALL）。

#### Scenario: カレンダーだけが取得できない
- **WHEN** 予定の読取が失敗し、他の内容は利用できる
- **THEN** 該当ソースは失敗と短く表示され、予約済みの確認なしに他の内容だけでPDFを生成できる

#### Scenario: 情報ソース列挙は自動
- **WHEN** アプリを起動する
- **THEN** デスクトップソースが自動で列挙され、利用者は手動で一覧表示のボタンを押さずに済む

#### Scenario: 各行の状態表示
- **WHEN** ソース一覧を見る
- **THEN** 各チェック行の右近くに「成功」「失敗」「パスワードが必要」のような短い状態語だけが出て、行間に長い説明がはさまらない

#### Scenario: そのままの状態でも失敗原因が砝別できる
- **WHEN** 親コレクションが`awaiting-credentials`で資格未登録のCalDAVソースを表示する
- **THEN** 失敗ではなく「パスワードが必要」と示し、利用者に長い説明を出さない

### Requirement: 設定の保存
利用者が表紙の名前・MET Norway用の連絡先・ソースや項目の選択・紙アプリ等の選択を再入力せずに済むように、アプリは設定を端末内の専用ファイルへ保存しなければならない（SHALL）。取得した連絡先や写真の内容そのものを保存してはならない（MUST NOT）。

#### Scenario: 再起動時の復元
- **WHEN** 利用者が設定を保存してからアプリを開き直す
- **THEN** 言語・表紙の名前・連絡先・選択中のソースと項目が元に戻される

#### Scenario: 保存と削除操作
- **WHEN** 利用者が設定を保存する
- **THEN** 保存はアプリ専用ファイルへの原子置き換えで行われ、個人の接続先や写真バイト列はディスクに載らない

### Requirement: 連絡先と予定とタスクの分離
連絡先・予定・TODOは別々のページに配置しなければならない（SHALL）。連絡先のページに予定やタスクを混在させない。予定のパネルは見出しで種別をまとめ、各行に種別名を繰り返し付けてはならない（MUST NOT）。

#### Scenario: 連絡先ページの見やすさ
- **WHEN** 利用者が連絡先ページを開く
- **THEN** 連絡先だけが表示され、種別名は見出しにまとめられ、各行には名称だけが出る

### Requirement: 配布環境でのデスクトップ連携
配布されたGNOMEアプリはホストの予定・タスクリスト・アドレス帳、位置情報、ファイル保存と印刷に必要最小限の権限で接続し、未設定の場合は設定案内を提供しなければならない（SHALL）。

#### Scenario: タスクリストが未登録
- **WHEN** デスクトップ側に利用可能なタスクリストが登録されていない
- **THEN** 「未完了タスクがない」状態と区別し、CalDAVタスクリストを登録するための案内を表示する
