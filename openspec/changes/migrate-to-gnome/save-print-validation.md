# PDF保存と印刷の実証記録(タスク2.6)

## 現在の結果

2026-11-08にネイティブのGNOME環境(Waylandセッション)で、保存・印刷ダイアログの操作、取消、保存時の権限不足を確認した。初回の空白ページ出力を修正後、対話試験を再実施し、本文入りPDFの保存と印刷操作の受理を確認した。利用者が承認した範囲（ネイティブ実証）でタスク2.6を完了とし、Flatpak内の再試験はタスク8.3に引き継ぐ。実紙の出力完了・可読性は未確認であり、印刷操作の受理と区別する。

## 実装物

- `tools/probe_save_print.py`: 実証専用のGTKアプリ。順に (1) 書込み禁止ディレクトリへの自動EXPORT試験、(2) `Gtk.FileDialog.save()` による保存、(3) `Gtk.PrintOperation` の `PRINT_DIALOG`、を出す。出力は分類と成功条件の集合値のみで、パスやドメイン以外のエラー詳細は出さない。自動再試行はしない。`--skip-denied`/`--skip-print`/`--save-dir` で部分実行できる。
- PDFの検証は `Poppler.Document.new_from_stream`(非推奨の `new_from_data` の代替)でページ数を読む。

## 実証結果の集計

- **権限不足**: 書込み禁止(0o500)のディレクトリをEXPORT先にした場合、`GLib.Error` の `gtk-print-error-quark` で失敗し、`denied_save_blocked=True`(実測)。
- **保存**: 初回は描画処理の未接続により空白だった。修正後の対話試験では、既存ファイルではない保存先へのEXPORTがAPPLYとなり、PDF魔数・1ページ・抽出テキスト「Paper Phone」を確認した（save_ok=True、saved_pdf_contains_probe_text=True）。ダイアログなしの一時PDF出力でも同じ検証が成功した。ファイルサイズだけでは内容の描画成功を判定しない。
- **保存の取消**: `save_cancelled=True` を別枠試行で確認。
- **印刷**: 修正後の本文描画処理を接続した試行でAPPLY（print_result=1、print_cancelled=False）を確認した。別試行でCANCELも確認した。APPLYはGTK側の操作受理であり、プリンタでの出力完了や実紙の内容は未確認。プリンタ名は採取していない。
- **利用プロセスの観測(ハーネス環境)**: 実証スクリプトの実行シェルは `$HOME` への書込みが禁止されており(書込みでOSError)、ホーム側の既定保存先は常に権限不足になる。これは実証プロセス側の制約であり、一般の利用者環境でホームが書込み不可という意味ではない。保存 Dialog 既定はプロジェクト内の `--save-dir`(書込み可能)に絞って実証した。

- Flatpakサンドボックス内の保存・印刷(ポータル・XDGプリントフローを含む)の実証はタスク8.3で実施する。`filesystem=home` 等の追加許可を最小限に保てるかを含む。
