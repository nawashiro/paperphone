# 冊子のプレビュー・保存・印刷

## 同じPDFの使い回し（タスク7.5）

[出力ビュー](<../src/paperphone/pdf_output.py>)は生成済みPDFのバイト列をメモリ内だけで受け取る。プレビュー・PDF保存・印刷は同じ不変スナップショットを読み、出力操作で内容を変えない。生成後に選択やソースを変えても既存のPDFは変わらない。

プレビューはPopplerでページを描画し、保存と印刷は同じPoppler文書を入力にする。個人的な出力履歴やPDFキャッシュは作らない。

## PDFの保存

保存は利用者が押した時だけGTKのFileDialogを開く。リモートの場所は保存先にせず、ローカルのファイルへの保存だけを扱う。既存ファイルは開いて切り詰めず、同じフォルダーに0600の一時ファイルを作り、fsync後にos.replaceで置換する。取消・拒否・書込失敗では既存ファイルを保ち、一時ファイルを消す。置換は保存ダイアログの成功以外で起きない。

## 印刷と案内

印刷はGTKのPrintOperationを使い、Points尺度でA4横向き・用紙1枚にPDF1ページ・100%（実際のサイズ）を案内する。「用紙に合わせる」を無効にする案内を表示する。両面の綴じ方向は実紙で未検証のため、事前にプリンター側で確認するよう案内する。物理印刷の完了は出力操作の受付だけで判断せず、「実紙の印刷完了は未確認」を明示する。

折り方の案内は、追加地図ページを裏面に印刷する場合と主ページだけの場合の両方が分かるように表示する。カード用ガイドの切り込み操作も含める。案内には折り方そのものだけを示す（2026-11-08の利用者判断で、両面の綴じ方向や「印刷結果をよく見てから折る」といった免責的な指示を含めない）。

## 検証範囲

- 偽ファクトリで保存バイト列の一致・既存ファイル保護・リモート拒否・書込失敗時のクリーンアップ・取消時の無変更を確認する。
- 偽印刷先でPopplerページの順序・ラスタ一致、コールバック失敗・取消・エラー時の「成功としない状態表示」を確認する。
- 実のGtk.PrintOperationをEXPORT動作で呼び、ダイアログや実プリンターを開かずにdraw-pageの描画・ページ数・抽出文字・状態文を確認する。
- プレビュー・保存・印刷が同一バイト列とページ表示を共有すること、clear/close/再生成が確定前の操作を無効にすることを確認する。
- 宅内プリンターでの実紙印刷・出力向き・折り畳み一致は未検証であり、確認は利用者の試験とタスク8.4で行う。
