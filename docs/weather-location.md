# 天気用の現在地取得（タスク5.1）

天気の取得には、利用者がボタンを押して許可したPCの現在地を用いる。座標をMET Norwayへ送信することを画面に説明し、座標と予報はメモリ内だけに保持する。起動時の自動取得・継続追跡・失敗後の自動再要求は行わない。

## 精度と失敗

- 精度の上限値は設けない。座標と精度が数値で範囲内（緯度−90〜90・経度−180〜180・精度は非負）なら送信し、非有限・範囲外・不正値は「不正値」として表示して天気サービスへ送らない。2026-11-08の追加判断でかつての10km上限を撤去した。
- 利用者の拒否、ポータル待ちのタイムアウト、サービス利用不能、天気取得失敗を別々に表示する。
- 天気が利用できなくても連絡先など他の印刷対象を選択できる。

## 実装と統合

[接続コントローラー](<../src/paperphone/weather_location.py>)は、[位置情報ポータル](<../src/paperphone/location.py>)からの座標を検査して[天気クライアント](<../src/paperphone/weather.py>)へ渡す。HTTP処理はワーカー、状態表示はUIスレッドで行う。[GTKビュー](<../src/paperphone/weather_location_view.py>)は、`Gtk.Window.export_handle`が存在するGIバインディングでのみWaylandの親ハンドルを取得し、それ以外では`parent_window=""`で要求する。現在のGTK 4.24のPyGObject公開には`export_handle`が含まれておらず、この環境ではX11のxid取得・Waylandの外部トークンどちらも得られない。

ビューの生成には識別情報を設定したWeatherClientを注入する。実連絡先やAPIキーをコードへ埋め込まない。ホスト画面は破棄時にビューのclose()を呼ぶ。既存の他の選択ビューと同様、全画面への組込みはタスク8.1で行う。

## 予報と紙面

[時刻選択](<../src/paperphone/weather_selection.py>)はシステムの今日の9・12・18時を順番に処理し、前後90分以内で最も近い異なる1時間予報を選ぶ。同距離なら後を優先する。欠損を別枠・別日・中期予報で埋めない。18時枠の選択窓が閉じた後は取得そのものを行わず、「今日の天気はもうありません。」とだけ示す。

[紙面モデル](<../src/paperphone/weather_sheet.py>)は目安枠と実予報時刻を区別し、瞬間の気温・天気の対象期間・取得時刻・再確認時刻・有効期限を保持する。未知コードは元の値と未知表示を残し、既知の天気へ置換しない。画面と共通生成スナップショットには同じ投影データを渡す。タイムゾーン変更時は新しいモデルを生成し、既存の生成スナップショットは変えない。

[天気ブロック描画](<../src/paperphone/weather_rendering.py>)はCairo/Pangoで本文と出典を分離し、MET Norway由来の抜粋・整形であること、CC BY 4.0と参照URLをPDFへ載せる。本文の超過は呼出し元に返し、帰属そのものが収まらない領域はエラーとする。冊子配置と超過警告の画面統合は7章・8.1で行う。

HTTPキャッシュはメモリ内だけとし、Expires前は再利用、期限後はLast-Modified/ETagで条件付き確認する。期限不明・不正応答・通信失敗では少なくとも10分の間隔を設け、429のRetry-Afterを尊重する。期限切れと有効期限不明を最新と偽らず、表示にも区別を残す。アプリID・版・連絡先はUser-Agentにだけ使い、座標入りURL・応答・識別用連絡先をログやディスクキャッシュへ保存しない。

実位置取得・MET Norwayへの新たな実通信は今回のテストでは行っていない。合成座標と偽ポータルで拒否・タイムアウト・精度境界を、GTKの操作テストで失敗表示後も連絡先を印刷対象に選べることを確認する。
